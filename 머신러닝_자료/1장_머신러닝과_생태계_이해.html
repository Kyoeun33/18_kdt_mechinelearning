머신러닝의 개념

기계가 "학습"한다는 게 무슨 뜻일까? 가장 기본적인 직관부터 잡아봅니다.

머신러닝의 개념

머신러닝이란 무엇인가?

한 줄로: 데이터에서 규칙을 스스로 찾아내는 것

💡 비유 · 아이에게 고양이 가르치기

아이에게 "고양이는 귀가 뾰족하고 수염이 있고…"라고 규칙을 말로 설명하기는 어렵죠. 대신 고양이 사진을 수백 장 보여주면 어느새 처음 보는 고양이도 알아맞힙니다. 머신러닝도 똑같아요. 규칙을 우리가 짜주는 게 아니라, 예시(데이터)를 잔뜩 주면 컴퓨터가 규칙을 스스로 익힙니다.

📌 핵심 단어 두 개만 기억하세요: 데이터(예시) → 모델(찾아낸 규칙).

머신러닝의 개념

전통적 프로그래밍과 무엇이 다른가

전통적 프로그래밍

사람이 규칙을 직접 코드로 작성

규칙 + 데이터 → 정답

예: "이메일에 '무료', '당첨'이 있으면 스팸" 같은 규칙을 사람이 일일이 입력

머신러닝

기계가 규칙을 스스로 발견

데이터 + 정답 → 규칙(모델)

예: 스팸/정상 메일 수만 건을 주면, 기계가 "어떤 단어 조합이 스팸인지"를 직접 학습

🔑 그래서 머신러닝은 규칙이 너무 복잡하거나 사람이 말로 설명하기 어려운 문제(이미지 인식, 추천, 번역)에 강력합니다.

머신러닝의 3가지 큰 갈래

🎮강화학습

보상을 통해 시행착오로 학습. 게임 점수를 올리며 잘하는 법을 터득.

💡 비유

데이터 전쟁

왜 다들 "데이터, 데이터" 할까?

머신러닝의 성능은 알고리즘보다 데이터의 양과 질에 크게 좌우됩니다.

  • 좋은 재료가 있어야 좋은 요리가 나오듯, 좋은 데이터가 있어야 좋은 모델이 나옴
  • 그래서 구글·네이버·쿠팡 같은 회사가 데이터를 핵심 자산으로 여김
💡 비유 · 요리

최고의 셰프(알고리즘)도 신선한 재료(데이터)가 없으면 맛을 못 냅니다. 반대로 평범한 알고리즘도 좋은 데이터가 많으면 꽤 괜찮은 결과를 냅니다. 그래서 현업에서는 데이터 수집·정제에 가장 많은 시간을 씁니다.

📌 실무 팁: 데이터 분석가·ML 엔지니어의 업무 시간 중 약 70~80%가 데이터 다듬기라는 말이 있을 정도예요. 그래서 오늘 배울 넘파이·판다스가 중요합니다.

SECTION 03

넘파이 (NumPy)

모든 머신러닝 라이브러리가 그 위에서 돌아가는 토대. 숫자 묶음을 빠르게 다루는 법.

넘파이 개요

왜 리스트로 안 하고 넘파이를 쓸까?

  • 파이썬 리스트도 숫자를 담지만, 양이 많아지면 느립니다
  • 넘파이의 ndarray는 같은 계산을 수십~수백 배 빠르게
  • 행렬 계산·통계 함수가 한 줄로 끝남
💡 비유

리스트가 장바구니에 물건을 아무렇게나 담는 것이라면, ndarray는 규격 맞춘 칸막이 상자에 정리하는 것. 정리돼 있으니 한 번에 빠르게 처리할 수 있어요.

핵심 객체: ndarray (N-dimensional array)
import numpy as np array1 = np.array([1,2,3]) # 1차원 배열 생성 print(array1.shape) # (3,) → 원소 3개짜리 1차원
ndarray 개요

shape — 배열의 "모양"을 읽는 법

# 1차원: 원소 3개 np.array([1,2,3]).shape # (3,) # 2차원: 2행 3열 (표 모양) np.array([[1,2,3], [2,3,4]]).shape # (2, 3) array2.ndim # 2 → 차원(축)의 개수
💡 핵심 직관

shape는 "각 방향으로 몇 칸인가"를 알려주는 (행, 열) 숫자입니다. ML에서는 거의 항상 "내 데이터 모양이 뭐지?"부터 확인해요. (샘플 수, 특성 수) 형태가 가장 흔합니다.

📌 (3,) 처럼 쉼표 뒤가 비면 1차원이라는 뜻. (1, 3) 과 (3,) 은 다른 모양입니다!

데이터 타입

한 배열 = 한 가지 타입

타입은 섞이지 않고 통일됩니다
# 정수+문자 → 모두 문자로 통일 np.array([1, 2, 'test']).dtype # dtype('<U11') → 문자(string) # 타입 바꾸기: astype() arr = np.array([1,2,3]) arr.astype('float64') # [1. 2. 3.] → 실수로 변환
💡 비유 · 한 칸 한 종류

ndarray는 달걀판 같아요. 모든 칸에 같은 종류(달걀)만 들어갑니다. 숫자랑 글자를 섞으면 넘파이가 "그럼 다 글자로 통일할게" 하고 맞춰버립니다.

왜 중요? 같은 타입이라야 빠른 계산이 가능하기 때문!

편리한 생성

자주 쓰는 배열, 한 줄로 만들기

arange

np.arange(10) # 0~9 연속 숫자

range의 배열 버전

zeros

np.zeros((3,2)) # 0으로 채운 3×2

0으로 초기화

ones

np.ones((3,2)) # 1로 채운 3×2

1로 초기화

💡 언제 쓰나?

실험용 데이터를 만들거나, "일단 0으로 채운 빈 그릇"을 준비해 두고 값을 채워나갈 때 자주 씁니다. arange는 순서가 필요한 인덱스 만들 때 단골이에요.

reshape

모양 바꾸기 — reshape()

# 0~9 (10개) 를 2행 5열로 np.arange(10).reshape(2,5) # -1 = "알아서 계산해줘" np.arange(10).reshape(-1,5) # 열을 5로 맞추니 행은 자동 2
💡 비유 · -1의 마법

reshape(-1, 5) = "물건 10개를 한 줄에 5개씩 담아줘. 줄 수(행)는 네가 알아서 계산해." → 자동으로 2줄!

원소 개수가 안 맞으면(예: 10개를 3열로) 에러가 납니다.

📌 ML에서 데이터를 모델이 원하는 모양으로 맞출 때 정말 자주 씁니다. reshape(-1, 1)(세로 한 줄)도 단골 패턴!

인덱싱(Indexing)

원하는 값만 골라내기 — 4가지 방법

① 단일 값

arr[2] # 3번째 값 arr2d[1,0] # (2행,1열)

인덱스는 0부터! 음수는 뒤에서부터

② 슬라이싱(:)

arr[0:3] # 0,1,2번 arr2d[:2,1:]

범위로 잘라내기

③ 팬시 인덱싱

arr2d[[0,1]] # 0행, 1행만 콕 집어

리스트로 여러 개 한꺼번에

④ 불린 인덱싱 ⭐

arr[arr > 5] # 5보다 큰 값만

조건에 맞는 것만! 가장 많이 씀

🔑 특히 불린 인덱싱("조건을 주면 맞는 것만 쏙 뽑기")은 데이터 분석의 핵심 기술입니다. 판다스에서도 똑같이 쓰여요.

정렬 sort() · argsort()

정렬, 그리고 "순서의 위치"

# sort: 값을 정렬 np.sort([3,1,9,5]) # [1 3 5 9] # argsort: 정렬했을 때의 '원래 인덱스' np.argsort([3,1,9,5]) # [1 0 3 2]
💡 argsort가 왜 유용?

학생 점수를 정렬하면서, 동시에 그 순서대로 이름도 따라오게 하고 싶을 때!

idx = np.argsort(scores) names[idx] # 점수순 이름

📌 "성적순 등수", "추천 점수 높은 순 상품 정렬" 등 순위 매기기에 argsort가 단골로 등장합니다.

선형대수 연산

행렬 내적 · 전치 (가볍게 맛만)

# 내적(dot): 행렬 곱셈 np.dot(A, B) # 전치(transpose): 행↔열 뒤집기 np.transpose(A) # 또는 A.T
💡 지금은 이 정도만

내적·전치는 머신러닝 내부 계산의 기본 연산입니다. 지금 외울 필요는 없어요. "이런 게 있고, 넘파이가 한 줄로 해준다" 정도만 기억하면 충분합니다. 필요할 때 다시 봅니다.

🔑 딥러닝의 핵심 계산도 결국 거대한 행렬 곱셈의 반복입니다. 넘파이가 이걸 빠르게 처리해주는 거예요.

SECTION 04

판다스 (Pandas)

엑셀 표를 파이썬에서 자유자재로. 실무 데이터 분석의 진짜 주인공입니다.

판다스 시작

판다스 = 파이썬으로 쓰는 엑셀

  • DataFrame — 행과 열로 된 표 (엑셀 시트와 똑같이 생각하면 됨)
  • Series — 표의 한 개 열 (1차원)
  • CSV·엑셀 파일을 읽고, 필터링·집계·정제까지 코드로
💡 비유

엑셀은 마우스로 클릭클릭 하지만, 판다스는 코드로 합니다. 처음엔 엑셀이 쉬워 보여도, 데이터가 수십만 줄이 되면 코드가 압도적으로 빠르고 정확해요. 게다가 같은 작업을 반복·자동화할 수 있죠.

import pandas as pd df = pd.read_csv('titanic_train.csv') # CSV 파일 → DataFrame
기본 API

데이터를 처음 만나면 하는 일

df.head(3)

앞에서 3줄만 미리보기. "데이터가 어떻게 생겼지?" 첫 확인.

df.shape

(행 수, 열 수). "데이터가 몇 개지?" 규모 파악.

df.info()

각 열의 타입과 결측치 현황. "빈 값 있나?" 점검.

df.describe()

숫자 열의 평균·최대·최소 등 통계 요약.

💡 실무 루틴

새 데이터를 받으면 거의 항상 head → shape → info → describe 순서로 "탐색"부터 합니다. 마치 새 동네에 이사 가면 먼저 한 바퀴 둘러보는 것처럼요.

📌 df['Pclass'].value_counts() — 특정 열에 어떤 값이 몇 개씩 있는지 세기. 엄청 자주 씁니다.

상호 변환

리스트·딕셔너리 ↔ DataFrame

# 딕셔너리로 DataFrame 만들기 (key=열 이름) data = {'col1':[1,11], 'col2':[2,22], 'col3':[3,33]} df = pd.DataFrame(data) # DataFrame을 넘파이 배열로 다시 변환 df.values # → ndarray (모델에 넣을 때 자주)
💡 왜 변환을 알아야 하나?

현실에서는 데이터가 리스트·딕셔너리·CSV 등 제각각의 모양으로 옵니다. 또 판다스로 정제 → 넘파이로 변환 → 모델에 입력이 전형적인 흐름이에요. 그래서 둘 사이를 오가는 법이 중요합니다.

📌 기억할 다리: df.values 는 DataFrame을 넘파이 ndarray로 바꿔줍니다.

컬럼 생성·수정·삭제

열을 만들고, 고치고, 지우기

# 새 열 추가 (기존 열로 계산도 가능) df['Age_by_10'] = df['Age'] * 10 df['Family'] = df['SibSp'] + df['Parch'] + 1 # 열 삭제: axis=1 (열 방향) df.drop('Age_0', axis=1, inplace=True)
💡 axis 헷갈림 정리

axis=0 = 행(가로줄) 방향
axis=1 = 열(세로줄) 방향

"열을 지운다" → axis=1. 외우는 팁: 0은 위아래(행), 1은 좌우(열).

inplace=True = "원본을 직접 고쳐라"

⚠️ 피처 엔지니어링(기존 열로 새 열 만들기)은 모델 성능을 좌우하는 핵심 작업입니다. 여기서 그 기초를 배우는 거예요.

데이터 셀렉션

loc vs iloc — 헷갈리는 단짝

loc — 이름(라벨) 기준

df.loc['one', 'Name'] df.loc[df['Age']>60, ['Name','Age']]

loc = label(이름)으로 찾기

iloc — 위치(숫자) 기준

df.iloc[0, 0] df.iloc[:, -1] # 맨 끝 열

iloc = integer(숫자)로 찾기

💡 비유 · 아파트 찾기

loc는 "홍길동 씨 집"(이름표)으로 찾기, iloc는 "왼쪽에서 3번째 집"(위치 번호)으로 찾기. 둘 다 같은 집을 찾지만 기준이 다릅니다.

불린 인덱싱

조건으로 걸러내기 (실무 최다 사용 ⭐)

# 나이가 60살 초과인 승객만 df[df['Age'] > 60] # 여러 조건: & (그리고) | (또는), 각 조건은 ( ) 로 감싸기! df[ (df['Age']>60) & (df['Pclass']==1) & (df['Sex']=='female') ] # 60세 초과 + 1등석 + 여성 승객
💡 비유 · 검색 필터

쇼핑몰에서 "5만원 이하 + 무료배송 + 별점 4 이상" 필터를 거는 것과 똑같아요. 조건을 &로 이어 붙이면 됩니다. 단, 각 조건은 꼭 괄호로 감싸야 에러가 안 나요!

🔑 넘파이의 불린 인덱싱과 완전히 같은 개념. 한 번 익히면 평생 씁니다.

정렬 · 집계 · GroupBy

묶어서 요약하기 — groupby()

# 정렬 df.sort_values(by='Name') # 등급(Pclass)별로 묶어서 개수 df.groupby('Pclass').count() # 등급별로 여러 통계 한 번에 df.groupby('Pclass').agg( {'Age':'max', 'Fare':'mean'})
💡 비유 · 반별 평균

"학생 전체"를 "반별로 묶어서 평균 점수 내기"가 groupby예요. 엑셀의 피벗 테이블과 같은 일을 합니다.

"지역별 매출", "등급별 생존율"처럼 그룹별 인사이트를 뽑을 때 필수.

결손 데이터 처리

빈 칸(결측치) 다루기

# 빈 값(NaN)이 열마다 몇 개인지 세기 df.isna().sum() # 빈 값을 채우기 (fillna) df['Age'] = df['Age'].fillna(df['Age'].mean()) # 나이는 평균값으로 df['Embarked'] = df['Embarked'].fillna('S') # 항구는 'S'로
💡 왜 중요한가

현실 데이터엔 빈 칸이 정말 많습니다. (설문 미응답, 센서 오류 등) 대부분의 ML 모델은 빈 칸이 있으면 에러를 내요. 그래서 "어떻게 채울까(평균? 최빈값?)"를 정하는 게 데이터 전처리의 핵심 단계입니다.

📌 NaN = "Not a Number", 즉 비어있는 값. isna()로 찾고 fillna()로 채웁니다.

apply · lambda

열 전체에 나만의 규칙 적용하기

# lambda = 이름 없는 한 줄짜리 함수 df['Name_len'] = df['Name'].apply(lambda x : len(x)) # 이름 길이 # 나이를 어린이/어른으로 분류 df['Child_Adult'] = df['Age'].apply( lambda x : 'Child' if x <= 15 else 'Adult')
💡 비유 · 도장 찍기

apply는 "이 규칙을 모든 행에 한 번씩 도장 찍듯 적용해줘"라는 명령이에요. lambda는 그 규칙을 짧게 쓰는 법. 수만 줄도 한 줄 코드로 처리됩니다.

🔑 연속된 나이를 '어린이/청소년/성인' 같은 구간(범주)으로 묶는 것은 피처 엔지니어링의 단골 기법입니다.
