SECTION 01

사이킷런 소개와 핵심 용어

머신러닝의 '표준 도구'를 만나고, 앞으로 계속 쓸 기본 용어를 정리합니다.

사이킷런 소개

사이킷런(scikit-learn)이란?

🏆 표준

파이썬 머신러닝의 사실상 표준 라이브러리. 가장 많이 쓰이고 자료도 풍부.

🧩 일관성

어떤 모델이든 fit() → predict() 똑같은 방식. 하나 익히면 전부 응용.

📦 올인원

알고리즘 + 전처리 + 평가 + 예제 데이터까지 한 패키지에.

💡 비유 · 레고 블록

사이킷런은 규격이 통일된 레고 블록 세트 같아요. 모든 블록(모델)의 결합 방식(fit/predict)이 같아서, 한 번 조립법을 익히면 어떤 모델로 바꿔 끼워도 똑같이 작동합니다.

꼭 알아야 할 기본 용어

피처 · 레이블, 그리고 X와 y

피처(Feature) = X

예측에 사용하는 입력 데이터(속성). 붓꽃이라면 꽃잎 길이·너비 등. 보통 대문자 X로 표기.

레이블/타깃(Label) = y

우리가 맞히려는 정답. 붓꽃 품종(0/1/2). 보통 소문자 y로 표기.

💡 비유 · 문제집

피처(X)는 '문제', 레이블(y)은 '정답'입니다. 모델은 문제와 정답이 함께 있는 학습용 문제집(훈련 데이터)으로 공부한 뒤, 정답을 가린 시험지(테스트 데이터)로 실력을 평가받습니다.

📌 이 X / y 표기는 앞으로 모든 코드에서 계속 등장합니다. 지금 확실히 기억해두세요!

SECTION 02

첫 번째 머신러닝 — 붓꽃 품종 예측

단 몇 줄의 코드로 '꽃을 보고 품종을 맞히는' 모델을 직접 만들어 봅니다.

붓꽃(Iris) 데이터

머신러닝의 'Hello World', 붓꽃 데이터

  • 꽃 150송이의 측정값 데이터
  • 피처 4개: 꽃받침 길이·너비, 꽃잎 길이·너비
  • 품종 3종: setosa, versicolor, virginica → 0, 1, 2

즉, "꽃의 치수 4개를 보고 → 어떤 품종인지 맞히기" 문제입니다.

💡 왜 붓꽃부터?

데이터가 작고 깨끗해서 개념에만 집중할 수 있어요. 운전 연습을 텅 빈 주차장에서 시작하는 것과 같습니다. 복잡한 현실 데이터는 그 다음에.

머신러닝의 큰 그림

모든 지도학습은 이 4단계로 흐른다

① 데이터 분리
학습용 / 테스트용
→
② 학습
fit()
→
③ 예측

💡 비유 · 시험 준비

① 문제집을 공부용/모의고사용으로 나누고 → ② 공부용으로 학습하고 → ③ 모의고사를 풀고 → ④ 채점해서 실력을 확인. 머신러닝도 똑같습니다.

🔑 이 4단계는 2장부터 끝까지 반복되는 뼈대입니다. 모델만 바뀔 뿐, 흐름은 같아요.

① 데이터 로딩 & 분리

코드로 보기 ① — 데이터 준비

from sklearn.datasets import load_iris from sklearn.model_selection import train_test_split iris = load_iris() X = iris.data # 피처 (150 × 4) y = iris.target # 레이블 (품종 0/1/2) # 학습용 80% / 테스트용 20% 로 분리 X_train, X_test, y_train, y_test = train_test_split( X, y, test_size=0.2, random_state=11)
💡 random_state는 왜?

데이터를 무작위로 섞어 나누는데, random_state를 고정하면 매번 같은 방식으로 나뉩니다. "결과를 재현 가능하게" 만드는 장치예요. 숫자 값 자체는 아무거나 OK.

②③④ 학습 · 예측 · 평가

코드로 보기 ② — 단 4줄로 완성

from sklearn.tree import DecisionTreeClassifier from sklearn.metrics import accuracy_score dt_clf = DecisionTreeClassifier(random_state=11) # 모델 생성 dt_clf.fit(X_train, y_train) # ② 학습 pred = dt_clf.predict(X_test) # ③ 예측 print(accuracy_score(y_test, pred)) # ④ 평가 → 0.9333
🎉 결과 해석

정확도 0.9333 = 93.3%. 테스트한 30송이 중 28송이의 품종을 맞혔다는 뜻입니다. 고작 4줄로 첫 모델 완성! 핵심은 fit → predict 패턴. 앞으로 모든 모델이 이 방식입니다.

사이킷런 프레임워크 익히기

왜 모든 모델이 똑같이 작동할까? 그 뒤에 있는 'Estimator' 설계를 들여다봅니다.

Estimator & fit/predict

Estimator — 모든 모델의 공통 규격

  • 사이킷런의 모든 모델 = Estimator
  • Classifier(분류) + Regressor(회귀)
  • 둘 다 fit()(학습) · predict()(예측) 보유

🔌 콘센트 규격

전 세계 전자제품이 같은 콘센트에 꽂히듯, 모든 Estimator는 같은 메서드 규격을 따릅니다. 그래서 모델 교체가 한 줄 수정으로 끝나요.

📌 분류기 이름은 보통 ~Classifier, 회귀는 ~Regressor로 끝납니다. (예: RandomForestClassifier)

내장 예제 데이터

연습용 데이터가 이미 들어있다

from sklearn.datasets import load_iris iris = load_iris() print(type(iris)) # Bunch (딕셔너리 비슷한 객체) print(iris.keys()) # data, target, feature_names, target_names ... iris.data # 피처 값 (numpy 배열) iris.target # 정답 레이블 iris.feature_names # 피처 이름

SECTION 04

Model Selection — 똑똑하게 평가하기

"정확도 100%!"가 사실은 함정일 수 있습니다. 제대로 평가하는 법을 배웁니다.

학습/테스트 분리

왜 데이터를 나눠야 할까?

⚠️ 함정 · 시험문제 유출

학습한 데이터로 그대로 평가하면 정확도가 100%가 나옵니다. 하지만 이건 공부한 문제를 그대로 시험에 낸 것과 같아요. 처음 보는 문제(새 데이터)엔 형편없을 수 있죠.

# 그래서 데이터를 미리 나눕니다 X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3) # train으로 학습 → test(처음 보는 데이터)로 평가 → 진짜 실력 측정

🔑 일반화 성능(처음 보는 데이터에 대한 성능)을 재는 것이 머신러닝 평가의 핵심입니다.

교차 검증 · K-Fold

교차 검증 — 운에 기대지 않기

한 번만 나누면 "어쩌다 쉬운 문제만 시험에 나온" 운이 작용할 수 있어요. K-Fold는 데이터를 K조각으로 나눠, 돌아가며 한 조각씩 시험을 봅니다.

from sklearn.model_selection import KFold kfold = KFold(n_splits=5) # 5조각
💡 비유 · 5번의 모의고사

모의고사를 5번 보고 평균을 내면, 한 번의 운보다 훨씬 믿을 만한 실력이 나옵니다. 5-Fold = 5번 평가 후 평균. 단 한 번의 행운/불운을 걸러냅니다.

📊 예제 결과: 5번의 정확도가 [1.0, 0.96, 0.86, 0.93, 0.73] → 평균 0.9. 한 번만 봤다면 위험했겠죠?

Stratified K-Fold

Stratified — 골고루 나누기

⚠️ 일반 K-Fold의 문제

붓꽃을 순서대로 나누면, 한 조각이 전부 품종 0, 다른 조각이 전부 품종 1이 될 수 있어요. 이러면 학습엔 0·1만, 시험엔 2만 나와서 엉망이 됩니다.

💡 비유 · 조 편성

Stratified K-Fold는 각 조각에 품종을 원래 비율대로 골고루 섞어 넣습니다. 운동회 조를 짤 때 키 큰 사람·작은 사람을 각 조에 고르게 배분하는 것과 같아요. 분류 문제에선 거의 항상 이걸 씁니다.

cross_val_score

교차 검증, 이제 한 줄로

from sklearn.model_selection import cross_val_score scores = cross_val_score(dt_clf, X, y, scoring='accuracy', cv=3) print(scores) # [0.98 0.94 0.98] print(scores.mean()) # 0.9667
💡 편리함의 힘

앞서 K-Fold를 for문으로 직접 돌렸던 걸, cross_val_score가 한 줄로 끝내줍니다. (내부적으로 분류 문제엔 자동으로 Stratified 방식 적용!) 실무에선 이걸 많이 씁니다.

GridSearchCV

최적 설정값을 자동으로 찾기

# 시도해볼 설정값들을 딕셔너리로 params = {'max_depth':[1,2,3], 'min_samples_split':[2,3]} grid = GridSearchCV(dtree, params, cv=3) grid.fit(X_train, y_train) grid.best_params_ # 최적 조합 grid.best_score_ # 그때 정확도
💡 비유 · 최적 레시피 찾기

하이퍼파라미터 = 요리의 '불 세기·소금 양' 같은 설정값. GridSearchCV는 가능한 조합을 전부 시도해보고 가장 맛있는(성능 좋은) 레시피를 자동으로 찾아줍니다.

📌 하이퍼파라미터 = 사람이 미리 정해주는 모델 설정값. 모델이 학습으로 알아내는 값과 구별돼요.

SECTION 05

데이터 전처리

모델은 깨끗하게 손질된 숫자만 먹습니다. 날것의 데이터를 모델이 먹을 수 있게 다듬는 법.

왜 전처리가 필요한가

모델은 '숫자'만, 그리고 '깨끗한' 숫자만

🔤 → 🔢 문자

'남/여', '서울' 같은 문자는 숫자로 변환해야 함 (인코딩)

🕳️ 결측치

빈 칸(NaN)이 있으면 채우거나 제거

📏 스케일

값의 범위가 제각각이면 크기를 맞춰줌 (스케일링)

💡 비유 · 요리 손질

아무리 좋은 재료도 씻고, 껍질 벗기고, 알맞게 썰어야 요리에 들어갑니다. 전처리는 데이터의 '손질' 과정. 이 단계가 모델 성능의 절반 이상을 좌우해요.

데이터 인코딩 ①

레이블 인코딩 — 문자를 숫자로

from sklearn.preprocessing import LabelEncoder items = ['TV','냉장고','전자레인지','컴퓨터'] encoder = LabelEncoder() labels = encoder.fit_transform(items) print(labels) # [0 1 4 5 ...] 각 문자에 숫자 배정
💡 단순하지만 함정이 있어요

'TV'=0, '냉장고'=1처럼 번호표를 붙이는 방식. 간단하지만, 모델이 "5(컴퓨터) > 0(TV)니까 더 중요해"라고 크기를 오해할 수 있습니다. 그래서 다음 장의 원-핫 인코딩이 등장합니다.

데이터 인코딩 ②

원-핫 인코딩 — 크기 오해 방지

# 판다스로 가장 간편하게 pd.get_dummies(df) # TV 냉장고 컴퓨터 # 1 0 0 ← TV # 0 1 0 ← 냉장고 # 0 0 1 ← 컴퓨터
💡 비유 · 출석 체크

각 항목마다 전용 칸을 만들고 해당하면 1, 아니면 0. 'TV냐?' '냉장고냐?'를 따로 체크하니 크기 비교 오해가 사라집니다. 순서·크기 의미가 없는 범주(색깔, 도시 등)에 적합.

🔑 정리: 숫자에 순서 의미가 있으면 레이블 인코딩, 없으면 원-핫 인코딩을 고려.

피처 스케일링

크기 맞추기 — Standard / MinMax

StandardScaler

평균 0, 분산 1로 변환 (표준화)

대부분의 경우 무난한 기본 선택

MinMaxScaler

💡 비유 · 단위 통일

키(170cm)와 몸무게(65kg)는 단위가 달라 그대로 비교하면 키가 더 '커' 보입니다. 스케일링은 모두 같은 잣대로 환산해, 특정 피처가 단지 숫자가 크다는 이유로 과한 영향을 주는 걸 막아요.

스케일링 유의점 (중요!)

테스트 데이터엔 fit() 하지 마라

# ✅ 올바른 순서 scaler.fit(X_train) # 기준은 '학습 데이터'로만 정함 X_train_scaled = scaler.transform(X_train) X_test_scaled = scaler.transform(X_test) # 테스트엔 transform만!
⚠️ 왜?

테스트 데이터에 다시 fit()하면 학습 때와 기준(잣대)이 달라져 버립니다. 이는 시험 직전에 채점 기준을 몰래 바꾸는 것과 같아요. 반드시 학습 데이터 기준을 그대로 적용(transform만)해야 합니다.

🔑 이 실수는 초보자가 가장 자주 하는 것 중 하나. 면접 단골 질문이기도 합니다!
