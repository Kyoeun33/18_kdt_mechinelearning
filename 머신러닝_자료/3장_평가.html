평가
Evaluation

"정확도 95%!"... 그런데 이 모델이 정말 좋은 걸까요? 정확도가 거짓말을 하는 순간을 폭로하고, 모델을 제대로 꿰뚫어 보는 평가 지표들을 배웁니다.

파이썬 머신러닝 완벽 가이드 · 강의자료
2장 복습 & 3장 목표

"좋은 모델"을 고르려면, 잘 재야 한다

✅ 2장에서

모델을 만들고 정확도(accuracy)로 평가했습니다. 타이타닉 86.6% 등.

🎯 3장에서

정확도 하나로는 부족합니다. 오차행렬·정밀도·재현율·F1·ROC-AUC로 모델을 입체적으로 평가합니다.

💡 비유 · 건강검진

몸무게 하나로 건강을 판단할 순 없죠. 혈압·혈당·콜레스테롤을 여러 각도로 봐야 합니다. 모델 평가도 마찬가지 — 지표 하나에 속지 않는 법을 배웁니다.

3장에서 배울 것

오늘의 지도

  • 정확도와 그 함정 — 정확도가 거짓말을 하는 순간 (불균형 데이터)
  • 오차 행렬 — 예측 결과를 4칸으로 쪼개 보기
  • 정밀도와 재현율 — 무엇을 더 중요하게 볼 것인가 (+트레이드오프)
  • F1 스코어 — 정밀도와 재현율의 균형점
  • ROC 곡선과 AUC — 모델의 종합 분별력
  • 피마 인디언 당뇨병 예측 — 재현율이 생명을 살리는 실습
SECTION 01

정확도, 그리고 그 함정

가장 직관적인 지표지만, 가장 잘 속이는 지표이기도 합니다.

정확도(Accuracy)

정확도 — 가장 직관적인 지표

정확도 = (맞게 예측한 개수) ÷ (전체 개수)

100문제 중 95개를 맞히면 정확도 95%. 쉽고 직관적이라 가장 먼저 쓰는 지표입니다.

⚠️ 하지만...

정확도는 데이터가 한쪽으로 치우쳐 있을 때(불균형) 우리를 완전히 속일 수 있습니다. 다음 슬라이드에서 그 충격적인 예를 봅니다.

정확도의 함정 (꼭 기억!)

"아무것도 안 하고" 90% 정확도?!

# 손글씨 숫자 중 '7'을 찾는 문제 # 전체 450개 중 7은 45개뿐 (10%) class MyFakeClassifier: def predict(self, X): return np.zeros(len(X)) # 무조건 "7 아님" # 결과 정확도: 0.900 (90%) 😱
⚠️ 왜 이런 일이?

데이터의 90%가 "7 아님"이라, 무조건 "아님"이라 찍어도 90%를 맞힙니다. 모델은 아무것도 학습하지 않았는데도요!

💡 비유 · 희귀병 검사

1000명 중 환자가 5명뿐이라면, 의사가 모두 "정상"이라고만 해도 정확도는 99.5%. 하지만 정작 환자 5명을 다 놓친 최악의 의사죠. 그래서 다른 지표가 필요합니다.

SECTION 02

오차 행렬 (Confusion Matrix)

예측이 '어떻게' 맞고 틀렸는지, 네 칸으로 쪼개서 보면 진실이 드러납니다.

오차 행렬

예측 결과를 4칸으로 나누기

예측: 양성(1)
예측: 음성(0)
실제 양성
TP
맞게 양성
FN
놓친 양성
실제 음성
FP
잘못 양성
TN
맞게 음성
💡 비유 · 화재 경보기

TP: 불 났는데 울림 (정상)
FP: 불 안 났는데 울림 (오작동)
FN: 불 났는데 안 울림 (최악!)
TN: 불 안 났고 안 울림 (정상)

앞 글자 T/F = 맞췄나?, 뒤 글자 P/N = 뭐라고 예측했나?

📌 모든 평가 지표(정밀도·재현율·F1)는 이 4칸의 조합으로 계산됩니다. 여기가 출발점이에요.

오차 행렬로 보는 진실

"90% 모델"의 정체

앞의 FakeClassifier 오차 행렬
confusion_matrix(y_test, fakepred) [[405 0] # TN=405, FP=0 [ 45 0]] # FN=45, TP=0
⚠️ 충격적 사실

TP = 0. 즉 정작 찾아야 할 '7'을 단 한 개도 못 맞혔습니다. 그런데도 정확도 90%! 오차 행렬을 보면 모델의 민낯이 드러납니다.

from sklearn.metrics import confusion_matrix 한 줄로 바로 확인할 수 있어요.

SECTION 03

정밀도와 재현율

"얼마나 정확히 찍었나" vs "얼마나 놓치지 않았나" — 상황에 따라 더 중요한 게 다릅니다.

정밀도 · 재현율

두 가지 다른 질문

정밀도 (Precision)

TP ÷ (TP + FP)

"양성이라 예측한 것 중 진짜 양성 비율"

= 내가 찍은 게 얼마나 정확한가

재현율 (Recall)

TP ÷ (TP + FN)

"실제 양성 중 내가 맞힌 비율"

= 진짜를 얼마나 안 놓쳤나

💡 비유 · 낚시

정밀도 = 잡은 물고기 중 '내가 노린 어종'의 비율 (헛손질 안 했나). 재현율 = 강에 있던 그 어종 중 내가 잡은 비율 (다 잡았나). 둘은 종종 한쪽을 올리면 다른 쪽이 내려갑니다.

무엇이 더 중요한가

상황이 지표를 결정한다

🏥 재현율이 중요

암 진단, 금융 사기, 코로나 검사. 진짜를 놓치면(FN) 큰일나는 경우. "조금 헛검사(FP)해도 좋으니 절대 놓치지 마라."

📧 정밀도가 중요

스팸 메일 분류. 정상 메일을 스팸으로 잘못 분류(FP)하면 중요 메일을 잃음. "확실할 때만 스팸이라 하자."

💡 핵심 통찰

"좋은 모델"의 기준은 문제마다 다릅니다. 생명이 걸린 문제는 재현율, 사용자 불편이 걸린 문제는 정밀도. 비즈니스 목적을 먼저 이해하는 게 데이터 사이언티스트의 진짜 실력이에요.

코드로 보기

한 번에 평가하는 함수 만들기

from sklearn.metrics import accuracy_score, precision_score, recall_score, confusion_matrix def get_clf_eval(y_test, pred): print(confusion_matrix(y_test, pred)) # 오차 행렬 print(accuracy_score(y_test, pred)) # 정확도 print(precision_score(y_test, pred)) # 정밀도 print(recall_score(y_test, pred)) # 재현율 # 타이타닉 결과 → 정확도 0.866, 정밀도 0.825, 재현율 0.770
💡 실무 팁

이렇게 평가 지표를 묶은 함수를 하나 만들어두면, 모델을 바꿀 때마다 한 줄로 종합 평가가 가능합니다. 실무·캐글에서 다들 이렇게 해요.

정밀도/재현율 트레이드오프

임계값(Threshold)이라는 손잡이

모델은 사실 0/1이 아니라 '확률'을 예측합니다. (예: 생존 확률 0.55) 보통 0.5 이상이면 1로 판정하죠. 이 기준선이 임계값입니다.

# 확률 보기 lr_clf.predict_proba(X_test) # [[0.449, 0.551], ...] ← [0일확률, 1일확률]
💡 비유 · 합격 커트라인

임계값을 낮추면(0.4) → 더 많이 "양성"이라 함 → 재현율↑ 정밀도↓. 높이면(0.6) → 확실할 때만 양성 → 정밀도↑ 재현율↓. 시소처럼 움직입니다.

임계값 조정 실험

손잡이를 돌려보면 (타이타닉)

💡 읽는 법

임계값을 0.4→0.6으로 올릴수록 정밀도는 오르고(0.70→0.90) 재현율은 내려갑니다(0.82→0.72). 완벽한 정답은 없고, 문제 목적에 맞춰 손잡이를 조절합니다. (Binarizer로 구현)

정밀도와 재현율의 맹점

한쪽만 100%? 그건 속임수다

🎭 재현율 100% 만들기

전부 다 "양성"이라 찍으면 진짜 양성을 하나도 안 놓치니 재현율 100%! 하지만 정밀도는 바닥.

🎭 정밀도 100% 만들기

가장 확실한 1개만 "양성"이라 찍으면 그것만 맞아 정밀도 100%! 하지만 나머지를 다 놓쳐 재현율은 바닥.

그래서 둘을 함께 봐야 합니다. 이 둘을 하나로 합친 지표가 바로 다음에 배울 F1 스코어.

SECTION 04

F1 스코어

정밀도와 재현율, 둘 다 챙기고 싶을 때의 균형 지표.

F1 스코어

F1 — 정밀도와 재현율의 균형점

F1 = 2 × (정밀도 × 재현율) ÷ (정밀도 + 재현율)

= 두 값의 '조화 평균' (한쪽이 낮으면 F1도 크게 떨어짐)

💡 비유 · 균형 잡힌 식단

그냥 평균이 아니라 조화 평균이라, 정밀도·재현율 중 한쪽만 높으면 F1이 낮게 나옵니다. "둘 다 골고루 좋아야" 높은 점수를 주는, 깐깐한 지표예요.

from sklearn.metrics import f1_score f1 = f1_score(y_test, pred) # 타이타닉: F1 = 0.7966

🔑 정밀도/재현율의 우선순위가 딱히 없을 때, 또는 균형 잡힌 성능을 한 숫자로 보고 싶을 때 F1을 씁니다.

SECTION 05

ROC 곡선과 AUC

임계값을 전부 다 시도해보면, 모델의 '진짜 분별력'이 한 장의 그림으로 보입니다.

ROC 곡선

ROC 곡선 — 임계값 전체를 한눈에

  • 가로축 FPR: 음성을 양성이라 잘못 본 비율
  • 세로축 TPR(재현율): 양성을 맞게 본 비율
  • 임계값을 0~1로 바꿔가며 그린 궤적
💡 비유 · 곡선이 왼쪽 위로 붙을수록 좋다

좋은 모델일수록 곡선이 왼쪽 위 모서리로 바짝 붙습니다 (헛손질은 적게, 잘 맞히기). 대각선 점선은 '찍기(랜덤)' 수준 — 그보다 위에 있어야 의미 있는 모델이에요.

from sklearn.metrics import roc_curve — FPR, TPR을 반환해 그래프로 그립니다.

AUC

AUC — 곡선 아래 면적, 한 숫자로

1.0

완벽한 모델 (이상적)

0.9 내외

아주 우수 (타이타닉 0.8987)

0.5

찍기(랜덤)와 동일 — 쓸모없음

💡 비유 · 모델의 '시력 점수'

AUC는 ROC 곡선 아래 면적으로, 모델이 양성과 음성을 얼마나 잘 구분하는지를 0.5~1.0 한 숫자로 요약합니다. 1에 가까울수록 분별력이 좋다는 뜻. 불균형 데이터에서도 잘 작동해 많이 씁니다.

roc_auc_score(y_test, pred_proba) → 0.8987

SECTION 06

실습 — 피마 인디언 당뇨병 예측

재현율이 곧 '놓친 환자 수'가 되는, 의미 있는 실전 문제로 모든 지표를 적용합니다.

문제 소개

"이 사람은 당뇨일까?"

  • 임신 횟수, 혈당, 혈압, BMI 등 의료 데이터로 당뇨 여부(0/1) 예측
  • 로지스틱 회귀로 학습 → 5개 지표로 평가
💡 왜 재현율?

당뇨 환자를 놓치면(FN) 치료 시기를 놓칩니다. 그래서 이 문제는 재현율을 특히 신경 써야 해요. 정확도만 봐선 안 됩니다.

데이터 정제 (실무 인사이트!)

"0"이 사실은 빈 값이었다

# 혈당·혈압·BMI가 0? 사람이 그럴 리 없다 → 사실은 결측치! zero_features = ['Glucose','BloodPressure','SkinThickness','Insulin','BMI'] # 0을 평균값으로 대체 diabetes_data[zero_features] = diabetes_data[zero_features].replace(0, mean_values)
⚠️ 데이터를 의심하라

혈압이 0인 사람은 없습니다. 이런 '말도 안 되는 0'은 결측치가 0으로 기록된 것이에요. 이걸 못 보고 그냥 쓰면 모델이 망가집니다. 데이터를 비판적으로 들여다보는 눈이 실력입니다.

🔑 describe(), 히스토그램으로 분포를 꼭 확인하세요. 이게 진짜 데이터 사이언티스트의 습관!

성능 개선

스케일링 + 임계값 조정으로 재현율 살리기

# ① 스케일링으로 피처 크기 통일 X_scaled = StandardScaler().fit_transform(X) # ② 임계값을 0.5 → 0.48로 낮춰 재현율 개선 binarizer = Binarizer(threshold=0.48) pred = binarizer.fit_transform(pred_proba_1) # → 재현율이 올라가 당뇨 환자를 덜 놓치게 됨
💡 배운 것 총동원

2장의 스케일링 + 3장의 임계값 조정을 합쳐 성능을 끌어올립니다. "환자를 놓치지 않기"라는 목적에 맞게 임계값을 의도적으로 낮춘 거예요.

종합 평가

5개 지표를 한 번에

def get_clf_eval(y_test, pred, pred_proba): print(confusion_matrix(y_test, pred)) print(accuracy_score(...), precision_score(...), recall_score(...), f1_score(...), roc_auc_score(y_test, pred_proba)) # 오차행렬 + 정확도 + 정밀도 + 재현율 + F1 + AUC 를 한 방에!
💡 이 함수는 평생 씁니다

분류 문제를 풀 때마다 이 get_clf_eval 같은 종합 평가 함수를 만들어두면 편합니다. 4장 이후의 모든 분류 실습에서 계속 등장해요. 팀 프로젝트에서도 그대로 활용 가능!

오늘의 한 페이지 요약

🎯정확도의 함정

불균형 데이터에선 "다 0으로 찍어도" 90%. 정확도만 믿지 말 것.

🔲오차 행렬

TP·FP·FN·TN 4칸. 모든 지표의 출발점.

⚖️정밀도 vs 재현율

"정확히 찍기" vs "안 놓치기". 문제 목적이 우선순위를 결정. F1은 둘의 균형.

📈ROC-AUC

임계값 전체에 걸친 분별력. 1에 가까울수록 우수, 0.5는 랜덤.

✅ 이제 "정확도 95%!"라는 말에 "어떤 데이터로? 재현율은?"이라고 되물을 수 있다면, 3장은 성공입니다. 이게 전문가의 시선이에요.
