💡 NLP vs 텍스트 분석?

NLP(자연어 처리)는 기계가 언어를 '이해'하는 데 초점(번역·챗봇), 텍스트 분석은 텍스트에서 '의미 있는 정보·예측'을 뽑는 데 초점(감성·분류). 겹치는 부분이 많아요. 이 장은 텍스트 분석 관점입니다.

💡 Stemming vs Lemmatization

둘 다 단어를 원형으로 통일하지만, Stemming은 어미를 거칠게 자르고(빠름), Lemmatization은 문법·사전을 보고 정확한 원형을 찾습니다(느림). "amusing/amused → amuse"처럼요.

🔑 왜 원형 통일? "run / runs / running"을 같은 단어로 취급해야 빈도가 제대로 집계됩니다.

SECTION 03

BOW — 글을 숫자로 바꾸기

텍스트 분석의 심장. 단어를 세어서 글을 벡터(숫자 묶음)로 만듭니다.

Bag of Words

BOW = 단어를 자루에 담아 세기

"나는 영화를 봤다.
영화 재밌다."
→
나는:1영화:2봤다:1재밌다:1
💡 비유 · 단어 주머니

문장의 순서는 무시하고, 어떤 단어가 몇 번 나왔는지만 자루에 담아 세는 방식. "영화"가 2번 나왔으니 영화 칸에 2. 단순하지만 강력해서, 텍스트 분석의 기본 중의 기본입니다.

⚠️ 한계: 순서·문맥을 무시함. ("개가 사람을 물다" = "사람이 개를 물다"로 취급) → 그래서 n-gram, 딥러닝이 발전했어요.

Count vs TF-IDF

두 가지 벡터화 방식

Count 벡터화

단순히 등장 횟수를 셈

흔한 단어(the)가 과대평가됨

CountVectorizer()

TF-IDF 벡터화 ⭐

자주 나오되 여러 문서에 흔하면 페널티

그 문서만의 특징적 단어를 강조

TfidfVectorizer()

💡 비유 · 특별한 단어 찾기

모든 리뷰에 "영화"가 나오면 변별력이 없죠. TF-IDF는 "이 문서엔 자주 나오지만, 다른 문서엔 드문" 단어에 높은 점수를 줍니다. 그 문서를 대표하는 키워드를 잘 잡아내요. 실무에선 보통 TF-IDF가 더 좋습니다.

희소 행렬

벡터화 결과는 '거의 0' — 희소 행렬

  • 전체 단어가 수만 개인데, 한 문서엔 수십 개만 등장
  • → 대부분이 0인 희소 행렬(sparse matrix)
  • COO·CSR 형식으로 0을 빼고 효율적으로 저장
💡 비유 · 출석부의 빈칸

전교생 명단(전체 단어)에서 우리 반(한 문서)에 해당하는 칸만 체크되고 나머지는 다 빈칸이죠. 빈칸(0)을 일일이 저장하면 낭비라, 체크된 위치만 기록하는 게 CSR 형식입니다.

📌 지금은 "벡터화 결과는 대부분 0이라 특수한 방식으로 저장한다"만 알면 충분. 사이킷런이 알아서 처리해줘요.

TF-IDF가 단순 Count 방식보다 나은 점은?
① 모든 단어를 똑같은 비중으로 센다
② 여러 문서에 흔한 단어는 낮추고, 그 문서만의 특징적 단어를 강조한다

SECTION 04

텍스트 분류 — 20 뉴스그룹

벡터화한 글을 4장의 분류 모델에 넣어, 뉴스가 어떤 주제인지 맞힙니다.

20 뉴스그룹 분류

뉴스 글의 주제를 맞혀보자

from sklearn.feature_extraction.text import TfidfVectorizer from sklearn.linear_model import LogisticRegression # ① 글을 TF-IDF로 벡터화 tfidf = TfidfVectorizer(stop_words='english') X_train_vect = tfidf.fit_transform(X_train) # ② 익숙한 분류 모델로 학습 → 약 20개 주제 분류 lr = LogisticRegression().fit(X_train_vect, y_train)
💡 핵심: 벡터화 후엔 평범한 분류

글이 숫자(벡터)가 되는 순간, 4장에서 배운 로지스틱 회귀·SVM 등을 그대로 씁니다. 텍스트라고 특별할 게 없어요. "벡터화가 8할"이라는 말이 그래서 나옵니다.

Pipeline & GridSearchCV

벡터화 + 모델을 하나로 묶기

from sklearn.pipeline import Pipeline pipeline = Pipeline([ ('tfidf', TfidfVectorizer(stop_words='english', ngram_range=(1,2))), ('lr', LogisticRegression(C=10)) ]) pipeline.fit(X_train, y_train) # 벡터화→학습을 한 번에!
💡 비유 · 컨베이어 벨트

Pipeline은 벡터화 → 학습을 한 줄로 이어 붙인 컨베이어 벨트입니다. 단계를 따로 관리할 필요 없고, GridSearchCV로 벡터화 옵션까지 한꺼번에 튜닝할 수 있어요. 실무 필수 패턴!

📌 ngram_range=(1,2): 단어 1개뿐 아니라 '두 단어 묶음'도 피처로 — 약간의 문맥을 살림.

SECTION 05

감성 분석 (Sentiment Analysis)

"이 리뷰는 긍정일까 부정일까?" 텍스트 분석에서 가장 인기 있는 응용.

감성 분석 개요

두 가지 접근법

지도학습 기반

긍정/부정 라벨이 있는 데이터로 학습

→ 평범한 분류 문제 (정확도↑)

예: IMDB 영화평 (라벨 있음)

비지도학습 기반

라벨 없이 감성 사전을 이용

단어별 긍/부정 점수를 합산

예: SentiWordNet, VADER

💡 언제 무엇을?

라벨 데이터가 있으면 지도학습(더 정확). 라벨이 없거나 새 도메인이면 감성 사전(비지도)으로 빠르게 시작. 둘 다 알아두면 상황에 맞게 골라 쓸 수 있어요.

지도학습 감성 분석 · IMDB

영화평 긍정/부정 맞히기

# ① 전처리: HTML 태그·특수문자 제거 (정규표현식) review_df['review'] = review_df['review'].apply(lambda x: re.sub("[^a-zA-Z]", " ", x)) # ② Pipeline: TF-IDF + 로지스틱 회귀 → AUC 0.93+ pipeline = Pipeline([('tfidf', TfidfVectorizer(...)), ('lr', LogisticRegression())])
💡 복습 총동원

정규표현식 정제(전처리) + TF-IDF(벡터화) + 로지스틱(분류) + AUC(평가, 3장) + Pipeline. 지금까지 배운 게 다 들어갑니다. 텍스트 분석이 어렵게 느껴져도, 결국 익숙한 조각들의 조합이에요.

비지도 감성 분석

감성 사전: SentiWordNet · VADER

📖 SentiWordNet

단어마다 긍정·부정·중립 점수가 매겨진 사전. 문장 속 단어 점수를 합산해 판정. 단어 의미(품사)를 고려.

⚡ VADER

SNS·소셜 미디어에 특화. 이모티콘·강조(!!!)·속어까지 반영. 빠르고 간편해 실무에서 인기.

💡 비유 · 감정 점수표

"좋다 +2, 최악 −3, 그냥 0" 같은 감정 점수표(사전)를 들고 문장의 단어 점수를 더해 총점이 양수면 긍정, 음수면 부정. 학습이 필요 없어 라벨 없이 바로 쓸 수 있는 게 장점이에요.

SECTION 06-08

토픽 모델링 · 문서 군집화 · 유사도

글 더미에서 숨은 주제를 찾고, 비슷한 문서끼리 묶고, 닮은 정도를 잽니다.

토픽 모델링 (LDA)

수천 개 문서의 숨은 주제 찾기

  • 많은 문서를 분석해 숨은 주제(토픽)를 자동 추출
  • 각 토픽 = 자주 함께 나오는 단어 묶음
  • LDA(잠재 디리클레 할당)가 대표 기법
from sklearn.decomposition import LatentDirichletAllocation lda = LatentDirichletAllocation(n_components=8)
💡 비유 · 도서관 자동 분류

사서가 수천 권을 일일이 안 읽고도, 자주 함께 등장하는 단어로 "이 책들은 스포츠, 저건 정치" 하고 주제를 묶어내는 것. LDA는 라벨 없이 문서 더미의 주제를 발견합니다 (비지도).

📌 LDA는 Count 벡터화와 함께 씁니다. (6장의 차원축소 LDA와는 다른 기법, 이름만 같아요!)

문서 군집화

비슷한 문서끼리 묶기

문서를 TF-IDF로 벡터화한 뒤, 7장의 K-평균으로 군집화하면 비슷한 내용의 문서끼리 묶입니다.

tfidf → KMeans(n_clusters=5) # 호텔 리뷰가 '청결/위치/가격' # 군집으로 자동 분류
💡 7장 + 8장의 결합

벡터화(8장)로 글을 숫자로 만들면, 7장의 모든 군집화 기법을 그대로 적용할 수 있어요. Opinion Review 실습에선 리뷰들을 주제별로 묶고 군집별 핵심 단어를 뽑아냅니다.

문서 유사도

코사인 유사도 — 두 글이 얼마나 닮았나

💡 비유 · 두 화살의 방향

각 문서를 벡터(화살표)로 보면, 두 화살이 같은 방향을 가리킬수록(사잇각이 작을수록) 유사합니다. 크기(글 길이)가 아니라 방향(내용)으로 비교하는 게 코사인 유사도예요.

  • 1에 가까움: 매우 유사
  • 0에 가까움: 관련 없음
from sklearn.metrics.pairwise import cosine_similarity cosine_similarity(vec1, vec2)

🔑 검색 엔진·추천("이 글과 비슷한 글")·표절 검사의 핵심 원리입니다. 9장 추천 시스템에서도 다시 등장!

한글 텍스트 처리

한글은 왜 더 까다로울까?

⚠️ 한글 NLP의 어려움

영어는 띄어쓰기로 단어가 나뉘지만, 한글은 조사·어미가 붙어("학교에서", "학교를") 단순 띄어쓰기로는 부족합니다. 형태소 분석(의미 단위로 쪼개기)이 꼭 필요해요.

from konlpy.tag import Okt okt = Okt() okt.morphs(text) # 형태소로 토큰화

💡 모든 것의 종합

텍스트 분석(8장) + 회귀(5장) + 인코딩(2장) + 로그 변환의 결합! 현실 문제는 텍스트·숫자·범주가 섞여 있죠. 이걸 다 합쳐 다루는 게 진짜 데이터 사이언스입니다.

📌 텍스트 분석은 단독으로도, 다른 데이터와 결합해서도 쓰입니다. Mercari는 후자의 좋은 예예요.

🧹전처리 & 벡터화
