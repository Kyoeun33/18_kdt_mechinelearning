SECTION 01-02

분류 개요와 결정 트리

모든 강력한 트리 기반 모델의 뿌리. 가장 직관적인 분류 알고리즘부터 시작합니다.

분류의 개요

분류 알고리즘 지도

분류 = 정답이 있는 데이터로 학습해 새 데이터의 범주(클래스)를 맞히는 지도학습. 종류가 많지만, 이 장은 트리 기반에 집중합니다.

🌳 트리 기반

결정 트리, 랜덤 포레스트, XGBoost, LightGBM (이 장의 주인공)

📐 선형/거리

로지스틱 회귀, SVM, KNN, 나이브 베이즈

🧠 신경망

딥러닝 (별도 영역)

🔑 왜 트리 기반? 정형 데이터(표 형태)에서 성능이 가장 좋고, 캐글 대회 우승 모델의 대부분을 차지하기 때문입니다.

💡 비유 · 스무고개

"이게 2.5보다 커요?" → "네/아니오"로 계속 질문을 던져 답을 좁혀갑니다. 결정 트리는 가장 잘 나누는 질문을 데이터에서 자동으로 찾아 위→아래로 분기합니다.

📌 장점: 사람이 이해하기 쉽다(규칙이 눈에 보임). 단점: 너무 깊어지면 과적합(다음 슬라이드).

결정 트리의 원리

"잘 나눈다"는 건 무슨 뜻일까?

  • 불순도(impurity): 한 그룹에 여러 클래스가 섞인 정도
  • 지니 계수 / 엔트로피로 측정
  • 트리는 불순도가 가장 많이 낮아지는 질문을 선택
💡 비유 · 빨래 분류

흰옷·색옷이 섞인 바구니(불순도 높음)를 질문 하나로 나눠 한쪽은 흰옷만, 한쪽은 색옷만(불순도 낮음) 되게 하는 것. 가장 깔끔하게 나누는 기준을 고릅니다.

📌 지금은 "트리가 가장 순수하게 나누는 기준을 자동으로 찾는다"만 기억하면 충분합니다. 공식 암기 불필요!

과적합과 주요 파라미터

너무 깊은 트리는 위험하다

⚠️ 과적합(Overfitting)

제약 없이 트리를 키우면 학습 데이터의 사소한 노이즈·예외까지 외워버립니다. 학습은 100점, 실전은 엉망. 결정 경계가 들쭉날쭉 복잡해져요.

max_depth

트리 최대 깊이 제한

min_samples_split

나누기 위한 최소 샘플 수

min_samples_leaf

잎(끝 노드) 최소 샘플 수

🔑 이 파라미터들로 트리가 너무 자잘하게 나뉘지 않도록 제어합니다. 비유하면 "스무고개 질문 횟수를 제한"하는 셈.

실습 · 사용자 행동 인식

스마트폰 센서로 행동 맞히기

# 561개 센서 피처로 6가지 행동(걷기/앉기 등) 분류 dt_clf = DecisionTreeClassifier(random_state=156) # GridSearchCV로 max_depth 튜닝 params = {'max_depth':[6,8,10,12,16,20,24]} grid = GridSearchCV(dt_clf, params, cv=5) # 최적 max_depth=16, 정확도 약 0.85
💡 피처 중요도

트리 모델은 어떤 피처가 분류에 많이 쓰였는지(feature_importances_)를 알려줍니다. "어떤 센서가 행동 구분에 결정적인가"를 알 수 있어 해석이 쉬운 게 큰 장점이에요.

📌 feature_importances_ → 막대그래프로 그려 상위 피처를 확인하는 게 실무 단골 패턴.

SECTION 03

앙상블 학습

"한 명의 천재보다 여러 명의 협력이 낫다." 여러 모델을 합쳐 더 강한 모델을 만듭니다.

앙상블 개요

앙상블 = 집단 지성

🗳️ 보팅 (Voting)

서로 다른 알고리즘들의 예측을 투표로 합침

🌲 배깅 (Bagging)

같은 알고리즘을 데이터 일부씩 나눠 여러 개 학습 (→ 랜덤 포레스트)

🚀 부스팅 (Boosting)

모델을 순차적으로 만들며 이전 오류를 보완 (→ XGBoost)

💡 비유 · 퀴즈쇼 찬스

어려운 문제를 방청객 다수에게 물어(보팅) 다수결로 답하면, 혼자 찍는 것보다 정답률이 높습니다. 앙상블의 핵심 직관이 바로 이거예요. "여럿이 모이면 똑똑해진다."

보팅 유형

하드 보팅 vs 소프트 보팅

하드 보팅 (Hard)

각 모델의 최종 예측(0/1)을 다수결

예: 3개 모델이 [1, 1, 0] → 1

소프트 보팅 (Soft) ⭐

각 모델의 예측 확률을 평균내어 결정

예: 확률 [0.9, 0.8, 0.4] 평균 0.7 → 1

💡 보통 소프트가 더 좋다

하드 보팅은 "1표는 1표"지만, 소프트 보팅은 "얼마나 확신하는지"까지 반영합니다. 자신 없는 표(0.51)와 확신하는 표(0.99)를 구별하니, 대체로 성능이 더 좋아요.

VotingClassifier

코드로 보기 — 보팅 분류기

from sklearn.ensemble import VotingClassifier lr_clf = LogisticRegression() knn_clf = KNeighborsClassifier(n_neighbors=8) # 두 모델을 소프트 보팅으로 결합 vo_clf = VotingClassifier(estimators=[('LR',lr_clf),('KNN',knn_clf)], voting='soft') vo_clf.fit(X_train, y_train) # 유방암 데이터 → 보팅이 개별 모델보다 정확도↑ (대체로)
💡 핵심

서로 성격이 다른 모델(로지스틱+KNN)을 묶을수록 효과가 큽니다. 비슷한 모델끼리는 같은 실수를 하니까요. "다양성"이 앙상블의 힘입니다.

SECTION 04

랜덤 포레스트

결정 트리 수백 그루를 심어 만든 '숲'. 배깅의 대표 주자입니다.

랜덤 포레스트

트리 하나 말고, 숲을 만들자

  • 여러 결정 트리를 데이터·피처를 무작위로 뽑아 학습
  • 각 트리의 예측을 투표/평균으로 종합
  • 과적합에 강하고, 성능도 안정적
💡 비유 · 여러 의사 진단

한 의사(트리 하나)는 실수할 수 있지만, 서로 다른 자료를 본 의사 100명의 의견을 모으면 훨씬 믿을 만합니다. '무작위성'이 각 트리를 다르게 만들어 다양성을 확보해요.

from sklearn.ensemble import RandomForestClassifier rf = RandomForestClassifier(n_estimators=100, random_state=0) # 트리 100그루
랜덤 포레스트 하이퍼파라미터

숲을 조율하는 손잡이들

n_estimators

트리 개수 (많을수록 안정적이지만 느려짐, 보통 100~300)

max_depth

각 트리의 최대 깊이 (과적합 제어)

min_samples_leaf

잎 노드 최소 샘플 수

max_features

분할 시 고려할 피처 수 (무작위성의 원천)

🔑 결정 트리의 파라미터 + 트리 개수(n_estimators). GridSearchCV로 튜닝하지만, n_jobs=-1로 CPU를 전부 써 속도를 높입니다.

SECTION 05-07

부스팅 — GBM · XGBoost · LightGBM

캐글 대회를 휩쓰는 절대 강자. '실수를 보완해 나가는' 방식의 위력을 봅니다.

부스팅 개요

부스팅 = 오답 노트 학습법

모델 1
일단 예측
→
틀린 부분
집중 표시
→
모델 2
틀린 것 보완
→
반복...
점점 강해짐
💡 비유 · 오답 노트

공부 잘하는 학생은 틀린 문제를 모아 다시 풉니다. 부스팅도 똑같아요. 앞 모델이 틀린 데이터에 가중치를 줘서 다음 모델이 그걸 집중 공략. 약한 모델을 이어 붙여 강한 모델로 만듭니다.

📌 배깅(병렬, 독립)과 달리 부스팅은 순차적(앞→뒤로 보완). 그래서 성능은 높지만 학습이 느릴 수 있어요.

GBM (Gradient Boosting)

GBM — 부스팅의 기본형

  • 오류(잔차)를 경사 하강법으로 줄여나가는 부스팅
  • 성능은 좋지만 학습이 느리다(순차적이라 병렬화 어려움)
from sklearn.ensemble import GradientBoostingClassifier gb = GradientBoostingClassifier(random_state=0)
⚠️ 느림이 약점

GBM은 정확하지만 학습 시간이 오래 걸립니다. 이 약점을 개선한 게 다음에 배울 XGBoost·LightGBM이에요. 그래서 실무에선 GBM 자체보다 그 후예들을 더 씁니다.

XGBoost

XGBoost — GBM의 강력한 업그레이드

⚡ 빠름

병렬 처리로 GBM보다 훨씬 빠른 학습

🛡️ 규제

과적합을 막는 규제(regularization) 내장

⏱️ 조기 중단

성능이 안 늘면 자동으로 학습 멈춤

💡 왜 캐글의 왕인가

GBM의 정확함은 유지하면서 속도·과적합 방지를 모두 개선했습니다. 한동안 캐글 정형 데이터 대회 우승을 독식했던 전설의 모델. 지금도 가장 많이 쓰입니다.

조기 중단 (Early Stopping)

"더 안 늘면 그만하자"

# 검증 데이터로 성능 모니터링 xgb.train(params, dtrain, num_boost_round=400, early_stopping_rounds=50, evals=eval_list) # 50번 동안 개선 없으면 자동 중단
💡 비유 · 운동 정체기

운동 효과가 50일째 안 나타나면 방법을 바꾸거나 멈추죠. 조기 중단은 트리를 400개까지 만들 수 있어도, 성능이 더 안 늘면 알아서 멈춰 시간 낭비와 과적합을 막습니다.

🔑 그래서 보통 학습용·검증용을 따로 두고(X_tr / X_val) 검증 성능으로 멈출 시점을 판단합니다.

XGBoost 사이킷런 래퍼

코드로 보기 — 익숙한 fit/predict

from xgboost import XGBClassifier xgb = XGBClassifier(n_estimators=400, learning_rate=0.1, max_depth=3) xgb.fit(X_train, y_train) # 사이킷런과 똑같은 fit/predict! pred = xgb.predict(X_test)
💡 두 가지 사용법

XGBoost는 파이썬 래퍼(고유 방식)와 사이킷런 래퍼(XGBClassifier)가 있어요. 초보자는 사이킷런 래퍼를 추천! 지금까지 배운 fit/predict가 그대로 통하니까요.

📌 핵심 파라미터: n_estimators(트리 수), learning_rate(학습률, 보통 0.01~0.2), max_depth.

LightGBM

LightGBM — 더 가볍고, 더 빠르게

  • XGBoost보다 훨씬 빠르고 메모리 적게 씀
  • 리프 중심(leaf-wise) 분할 — 더 깊고 효율적
  • 대용량 데이터에 특히 강함
from lightgbm import LGBMClassifier lgbm = LGBMClassifier(n_estimators=400)
⚠️ 작은 데이터엔 주의

LightGBM은 빠르지만 데이터가 적으면(보통 1만 건 이하) 과적합되기 쉽습니다. 데이터가 클 때 진가를 발휘해요. 작은 데이터엔 XGBoost나 랜덤 포레스트가 더 안전할 수 있습니다.

① 트리를 무조건 50개만 만든다
② 검증 성능이 50번 동안 개선 안 되면 학습을 멈춘다
③ 데이터를 50개씩 나눈다
정답: ② — 일정 횟수 동안 검증 성능이 안 늘면 자동으로 멈춰, 시간 낭비와 과적합을 막습니다. 부스팅 계열의 강력한 기능이에요.
SECTION 08

하이퍼파라미터 튜닝 — HyperOpt

GridSearch보다 똑똑하게, 베이지안 최적화로 최적값을 찾습니다.

베이지안 최적화

GridSearch의 한계를 넘어

GridSearchCV

가능한 모든 조합을 전부 시도

파라미터가 많아지면 경우의 수 폭발 → 매우 느림

베이지안 최적화 (HyperOpt)

이전 결과를 학습해 다음 후보를 똑똑하게 선택

적은 시도로 좋은 값에 빠르게 도달

💡 비유 · 보물찾기

GridSearch는 모든 칸을 다 파보는 무식한 탐색. 베이지안 최적화는 "여기 근처가 따뜻하니 더 파보자"처럼 단서를 활용해 효율적으로 찾습니다.

HyperOpt 사용법

3단계: 공간 → 목적함수 → fmin

# ① 탐색 공간 정의 search_space = {'x': hp.quniform('x', -10, 10, 1)} # ② 목적 함수 (작을수록 좋은 값을 반환) def objective_func(space): return space['x']**2 # 최소화할 대상 # ③ fmin으로 최적값 탐색 best = fmin(fn=objective_func, space=search_space, algo=tpe.suggest, max_evals=20)
💡 실전에선

목적 함수 안에서 XGBoost를 교차검증으로 학습하고, 그 성능(예: -ROC AUC)을 반환하게 만들면, HyperOpt가 최적 하이퍼파라미터를 자동으로 찾아줍니다.

SECTION 09-10

실전 실습 — 불균형 데이터와의 싸움

산탄데르 고객 만족, 신용카드 사기 검출. 현실의 '극단적 불균형' 데이터를 다룹니다.

산탄데르 고객 만족 예측

"이 고객은 불만족일까?"

  • 익명화된 피처 370개, 불만족 고객은 약 4%뿐 (불균형)
  • 이상값 처리(-999999 → 2), ID 제거 등 전처리
  • XGBoost·LightGBM으로 학습, ROC-AUC로 평가
💡 평가 지표 선택

불만족이 4%뿐이라 정확도는 무의미(3장 복습!). 그래서 ROC-AUC로 평가합니다. 불균형 데이터의 분별력을 보기에 적합하죠.

📌 피처가 370개나 되니, HyperOpt로 하이퍼파라미터를 튜닝해 성능을 끌어올립니다.

언더 샘플링 vs 오버 샘플링

불균형을 맞추는 두 방법

언더 샘플링

데이터 손실 위험 (정보 버림)

오버 샘플링 ⭐

적은 쪽(사기)을 늘린다

주로 SMOTE 사용 (다음 슬라이드)

💡 비유 · 토론 균형 맞추기

찬성 100명 vs 반대 3명인 토론은 한쪽으로 쏠립니다. 찬성을 줄이거나(언더), 반대를 늘려야(오버) 균형이 맞죠. 보통 정보 손실이 없는 오버 샘플링을 선호합니다.

로그 변환 & 이상치 제거

데이터의 모양 다듬기

📉 로그 변환

한쪽으로 쏠린(왜곡된) 분포를 고르게 펴줌. 거래 금액처럼 일부 값이 매우 큰 경우 효과적.

np.log1p(df['Amount'])

🎯 이상치 제거 (IQR)

너무 동떨어진 값을 사분위 범위(IQR) 기준으로 찾아 제거. 모델이 극단값에 휘둘리지 않게.

💡 비유 · 사진 보정

로그 변환은 너무 밝거나 어두운 사진의 명암을 고르게 펴는 것, 이상치 제거는 화면에 잘못 찍힌 점을 지우는 것. 둘 다 모델이 데이터를 더 잘 보게 돕습니다.

SMOTE 오버 샘플링

SMOTE — 그럴듯한 가짜 데이터 만들기

from imblearn.over_sampling import SMOTE smote = SMOTE(random_state=0) X_over, y_over = smote.fit_resample(X_train, y_train) # 학습 데이터에만! 적은 클래스를 합성으로 증식
💡 비유 · 빈칸 채우기

기존 사기 데이터들 사이사이에 그럴듯한 새 점을 만들어 수를 늘립니다. 단순 복사가 아니라 이웃을 보고 보간하는 방식. 단, 학습 데이터에만 적용(테스트엔 X)!

⚠️ 꼭 기억

SMOTE는 반드시 train_test_split 이후, 학습 데이터에만 적용합니다. 테스트 데이터에 적용하면 평가가 왜곡돼요. (3장 'fit 유의점'과 같은 원리)

💡 비유 · 전문가 패널 + 의장

여러 전문가(개별 모델)가 각자 의견을 내면, 의장(메타 모델)이 그 의견들을 종합해 최종 결정을 내립니다. 개별 모델의 예측 결과가 메타 모델의 입력 데이터가 되는 거예요.

📌 CV 세트 기반 스태킹: 과적합을 막기 위해 교차 검증 방식으로 메타 학습 데이터를 만드는 정교한 버전도 있습니다.
